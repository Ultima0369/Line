# Line — 带环境上下文的对话客户端

> 给 DeepSeek 的对话接上一组传感器读数：每次请求时，本地侧把当前环境
> （温湿度/气压/光照/噪声/系统状态）和注意力评估打包进 system prompt，
> 让云端模型的回复能参考你所在的物理环境。

```
   你 ──┐
        ▼
   ┌─────────────────────────────┐
   │  本地 · 边缘处理              │
   │  传感器读数 → 注意力评估      │
   │  → 打包紧凑上下文            │
   └──────────────┬──────────────┘
                  │ system prompt 注入环境上下文
                  ▼
   ┌─────────────────────────────┐
   │  云端 · DeepSeek             │
   │  深度推理，返回回复          │
   └─────────────────────────────┘
```

## 这是什么

一个 Python 客户端：传感器轮询 → 注意力筛选 → 把环境状态打包进云端请求
的 system prompt → DeepSeek 回复。本地侧不做推理（本地模型为占位，见路线图），
云端用 DeepSeek API。

它的实际能力：
- **环境感知对话**：回复时参考当前房间温湿度、气压、光照、噪声、系统状态
- **注意力调度**：传感器读数越过物理阈值（如高温）时，在对话流里注入环境事件
- **注意力驱动采样**：注意力分数不只注入 system prompt，还动态调整云端采样温度——高注意力（聚焦难题）时降温度求精确，低注意力（环境平稳）时升温度利发散。终端会显示当前 `T:温度`
- **主动环境推理**：本地侧（小脑）不被动等待输入——环境异常且过冷却期时，主动触发云端一轮独立思考（"小脑主动叫醒大脑"），把结论提示给用户。带冷却节流避免烧 token
- **模拟传感器**：无硬件也能跑（用带周期波动的模拟数据；注意：这是模拟，不是真实读数）
- **流式响应**：逐 token 返回云端输出

## 怎么用

```bash
# 1. 装依赖
pip install httpx pyyaml pydantic   # psutil 可选，用于系统传感器

# 2. 设置 API Key（用环境变量，不写进文件）
# Windows:
set DEEPSEEK_API_KEY=sk-你的key
# macOS/Linux:
export DEEPSEEK_API_KEY=sk-你的key

# 3. 开跑
python main.py
```

提示符后直接打字。`/sensors` 看环境数据，`/status` 看系统状态，`/clear` 清上下文，`/exit` 退出。

完整教程在 [docs/](docs/index.md)（中文）。

## 技术栈

| 层 | 技术 |
|----|------|
| 云端推理 | DeepSeek API（deepseek-reasoner / deepseek-chat） |
| 传感器 | 模拟（内置）/ 系统（psutil）/ 真实硬件（路线图） |
| HTTP | httpx（异步） |
| 语言 | Python 3.10+ |

## 路线图

- [x] 边缘→云端完整流程（传感器 → 注意力 → 打包 → API → 回复）
- [x] 模拟传感器（无硬件可体验）
- [x] 注意力调度接入真实控制流（阈值越界注入对话）
- [x] 注意力驱动云端采样（分数动态调整 temperature）
- [x] 主动环境推理（环境异常触发云端独立 reasoning turn，带冷却节流）
- [x] 流式响应
- [ ] 真实传感器硬件支持（树莓派 GPIO / I2C：DHT22, BMP280, BH1750）
- [ ] 本地小模型推理（当前为占位，加载逻辑需手动启用 transformers+torch）
- [ ] 注意力驱动的更多推理参数（max_tokens / 主动触发条件细化）
- [ ] 插件系统（自定义传感器、自定义注意力规则）
