# 06 · 语义协议

> **本地和云端之间的私有通信语言。**

---

## 为什么要压缩

你的每一次对话，在双脑模式下是这样的：

```
上行（本地 → 云端）:
  你的话 + 传感器数据 + 注意力状态 + 上下文摘要
  → 压缩为特征向量 + 紧凑文本

下行（云端 → 本地）:
  深度推理结果 → 解压为可读文本 + 操作建议
```

不压缩的话，每次都要把完整的传感器历史、对话历史、系统状态全传上去——贵，慢，没必要。

语义协议的核心思路是：**只传"增量"和"特征"，不传原始数据。**

---

## 上行编码（本地 → 云端）

### 传感器数据压缩

原始数据：

```json
{
  "temperature": [{"value": 26.5, "unit": "°C", "confidence": 0.95}],
  "humidity": [{"value": 58.2, "unit": "%", "confidence": 0.92}],
  "pressure": [{"value": 1013.0, "unit": "hPa", "confidence": 0.94}]
}
```

压缩后：

```
tmp:26.5|hum:58.2|prs:1013
```

从 ~200 字节 → ~30 字节。节省 85%。

### 注意力状态压缩

```python
# 原始
{"status": "active", "attention_level": 0.6, "dominant_sources": {...}}

# 压缩后
"l:0.6|s:active"
```

### 完整上行数据包

```json
{
  "version": "0.1.0",
  "timestamp": "2026-07-24T09:30:00",
  "type": "upstream",
  "user": "今天天气怎么样？",
  "sensor": "tmp:26.5|hum:58.2|prs:1013",
  "attention": "l:0.6|s:active",
  "context": "t:12|s:[摘要] 用户询问了温度..."
}
```

---

## 下行解码（云端 → 本地）

云端返回的推理结果：

```json
{
  "content": "根据传感器数据，当前温度26.5°C，湿度58.2%...",
  "reasoning": "用户想知道室外天气...",
  "confidence": 1.0
}
```

解压后提取：
- **响应文本**：直接显示给用户
- **推理过程**：可折叠展示
- **建议操作**：如"建议开窗通风"

---

## 压缩级别

在 `config.yaml` 中设置：

```yaml
protocol:
  compression_level: 3   # 1-5
```

| 级别 | 行为 |
|------|------|
| 1 | 几乎不压缩，保留完整上下文 |
| 2 | 轻度压缩，仅压缩传感器数据 |
| 3 | **默认**，中等压缩 |
| 4 | 高度压缩，截断长文本 |
| 5 | 极端压缩，仅传关键特征 |

---

## 私有协议的好处

1. **减少 API 调用成本** — 传输量减少 60-85%
2. **天然"加密"** — 压缩后的特征向量，没有协议字典的人读不懂
3. **可扩展** — 想传新类型的数据（如心率、眼动），只需在协议中加一个新字段
4. **版本控制** — 协议有版本号，新旧版本可共存
