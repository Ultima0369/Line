> **理解 Line 是怎么工作的。**

## 一句话架构

```
┌─────────────────────────────────────────────────────┐
│                    人类用户                          │
└────────────────┬────────────────────────────────────┘
                 │ 你说话
                 ▼
┌─────────────────────────────────────────────────────┐
│               本地 · 边缘处理                         │
│  ┌──────────┐  ┌──────────┐  ┌──────────────────┐  │
│  │ 传感器   │  │ 注意力    │  │ 上下文打包       │  │
│  │ 温湿度   │→│ 预筛选    │→│ 紧凑编码         │  │
│  │ 气压     │  │ 优先级    │  │ 对话摘要         │  │
│  │ 光照     │  │ 新奇度    │  │                  │  │
│  │ 噪声     │  │ 紧迫度    │  │                  │  │
│  └──────────┘  └──────────┘  └────────┬─────────┘  │

                                        ▼
```

---

## 三个核心模块

### 1. 传感器层（sensor/）

连接物理世界的接口。

- 支持：温湿度、气压、光照、噪声、系统状态（CPU/内存）
- 特性：即插即用、异步轮询、模拟模式（无硬件也可开发）
- 输出：标准化的 `SensorReading` 数据结构

### 2. 边缘处理器（edge/）

本地侧。负责：

- **注意力预筛选**：判断当前什么信息重要，什么可以忽略
- **上下文打包**：把传感器/注意力/对话状态编码成紧凑串
- **上下文管理**：维护对话历史，自动摘要
- **环境事件注入**：传感器读数越过物理阈值时，向对话流注入提示

> 本地小模型推理（本地直接回答简单问题）是路线图项，当前为占位，
> 实际推理都走云端。详见 README 路线图。

### 3. 云端桥接器（cloud/）

云端侧。负责：

- 调用 DeepSeek API（httpx 异步）
- 消费上行数据包，拼入 system prompt（含环境上下文）
- 进行深度推理
- 返回推理结果（支持流式）

---

## 数据流（一次完整的对话）

```
你说话 
  → 传感器采集环境数据 
  → 边缘处理器构建上行数据包（你的话 + 传感器紧凑串 + 注意力状态 + 对话摘要）
  → 云端消费上行包，拼入 system prompt
  → DeepSeek 深度推理
  → 解析返回（响应文本 + 推理过程）
  → 显示回复 + 记录到上下文
```

---

## 为什么这样设计

1. **减少延迟** — 传感器处理和注意力筛选在本地完成，不需要等云端
2. **省 token** — 传感器状态以紧凑串进 system prompt，而非完整 JSON
3. **环境感知** — 云端每次都拿到当前物理环境，回复能参考你所在的空间
4. **对话主权** — 你控制本地框架，云端是可插拔的推理引擎

> 注意：原始传感器数据**会**随请求上行到云端（编码进 system prompt）。
> 如果你的传感器数据需要保密，应靠 HTTPS（已默认）和网络层，而非这个打包格式。
> 本地小模型离线推理是路线图项，当前不可用。
